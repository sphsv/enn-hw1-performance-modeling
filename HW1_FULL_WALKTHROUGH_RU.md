## 1. В чём вообще состоит задание

Дана небольшая свёрточная нейронная сеть. На вход она получает `B`
квадратных изображений размером `S × S`.

Нужно построить аналитическую модель стоимости одного прямого прохода сети.
Она должна отвечать на четыре вопроса:

1. **FLOPs:** сколько вычислительных операций выполнит сеть?
2. **Memory:** сколько GPU-памяти потребуется на пике?
3. **Latency:** сколько времени займёт один forward pass?
4. **Energy:** сколько энергии потратит весь GPU?

Для latency и energy дополнительно нужно оценить `BytesMoved` — сколько байтов
все операторы сети суммарно прочитают и запишут.

Главная идея задания — не просто написать формулы, а сравнить их с настоящей
работой сети на GPU:

```text
архитектура
    ↓
аналитические формулы
    ↓
реальные измерения на GPU
    ↓
калибровка неизвестных параметров
    ↓
проверка на новых S и B
    ↓
графики и объяснение ошибок модели
```

Особый интерес представляют три режима:

- `launch-bound` — работа маленькая, основное время занимает запуск ядер;
- `memory-bound` — ограничением становится перенос данных;
- `compute-bound` — ограничением становятся вычислительные блоки GPU.

## 2. Что конкретно требовало условие

### 2.1. Реализовать точную CNN

Архитектура:

```text
Input: B × 3 × S × S

Conv 7×7, stride 2, 3→32
ReLU
MaxPool 3×3, stride 2, padding 1

Conv 5×5, 32→64
ReLU

Conv 3×3, stride 2, 64→128
ReLU

Conv 1×1, 128→256
ReLU

Conv 3×3, stride 2, 256→256
ReLU

Conv 1×1, 256→512
ReLU

Global Average Pooling
Linear 512→256
ReLU
Linear 256→100
```

Для всех свёрток:

- `padding = kernel_size // 2`;
- `bias=False`.

Для всех ReLU:

- `inplace=True`.

Режим работы:

- `model.eval()`;
- FP32;
- `torch.inference_mode()`.

### 2.2. Вывести четыре функции

```python
flops(image_size, batch)                 # FLOPs
memory(image_size, batch)                # bytes
latency(image_size, batch, theta)        # seconds
energy(image_size, batch, theta_energy)  # joules
```

Функции должны работать не только со скалярами, но и с NumPy-массивами с
broadcasting. Это позволяет одним вызовом получить целую поверхность по
значениям `S` и `B`.

### 2.3. Провести 132 измерения

Базовые размеры изображений:

Базовые размеры батча:

### 2.4. Обработать нехватку памяти

Большие конфигурации могут не поместиться на GPU. Нужно:

1. перехватить `torch.cuda.OutOfMemoryError`;
2. записать конфигурацию со статусом `OOM`;
3. не останавливать весь эксперимент;
4. сравнить реальный OOM с предсказанием формулы Memory.

### 2.5. Соблюсти протокол измерений

### 3.2. `models.py`: сама сеть

В `SmallCNN` реализована архитектура из задания:

- шесть свёрток;
- ReLU после каждой свёртки;
- один MaxPool;
- Global Average Pooling;
- классификатор `512→256→100`;
- отдельный ReLU между линейными слоями.

Свёртки не имеют bias. ReLU работают inplace. Проверенная форма выхода —
`B×100`.

Общее число параметров:

```text
1 040 324.
```

### 3.3. `equations.py`: аналитические функции

#### FLOPs

Сначала для каждой свёртки считается:

```text
2 · B · H_out · W_out · C_out · C_in · K².
```

Множитель 2 появляется из соглашения `1 MAC = 2 FLOP`.

Затем добавляются операции ReLU, MaxPool, Global Average Pooling и линейных
слоёв. После сложения получается:

```text
FLOPs(S,B) = B(17 751S² + 313 956).
```

Подробное происхождение каждого числа записано в
`HANDWRITTEN_DERIVATION_GUIDE.md`.

#### Memory

Исходный вход остаётся жив во время forward pass. Максимальный набор
одновременно живых активаций возникает во время первого MaxPool:

```text
исходный вход         3BS²
выход первой Conv     8BS²
выход MaxPool         2BS²
---------------------------
всего                13BS²
```

Добавляются `1 040 324` параметра модели, затем число элементов умножается на
4 байта FP32:

```text
Memory(S,B) = 4(1 040 324 + 13BS²) байт.
```

Формула намеренно не учитывает workspace cuDNN, внутренние буферы и эффекты
аллокатора. Их влияние должно быть рассмотрено в итоговом анализе.

#### BytesMoved

Для каждого из 17 операторов предполагается:

- один раз прочитан вход;
- один раз прочитаны веса и bias;
- один раз записан выход.

Кэши и fusion не учитываются. После суммирования:

```text
BytesMoved(S,B) =
4(91BS² + 2 148B + 1 040 324) байт.
```

#### Latency

Для каждого оператора `l` используются:

- `F_l` — FLOPs;
- `Q_l` — байты;
- `t_launch` — цена запуска;
- `P_eff` — эффективные FLOP/s;
- `BW_eff` — эффективные байт/с.

Послойная roofline-модель:

```text
Latency(S,B;θ) =
Σ_l [t_launch + max(F_l/P_eff, Q_l/BW_eff)].
```

Числа `t_launch`, `P_eff` и `BW_eff` не придумываются. Они подбираются по
реальным измерениям конкретной GPU.

#### Energy

Энергия моделируется как сумма стоимости запусков, вычислений и трафика:

```text
Energy(S,B;θ_E) =
17e_launch
+ e_flop·FLOPs(S,B)
+ e_byte·BytesMoved(S,B).
```

Коэффициенты должны быть неотрицательными и подбираются по измерениям энергии.

### 3.4. `measure.py`: реальные измерения

Код:

1. формирует полную сетку из 132 конфигураций;
2. перемешивает порядок измерений;
3. создаёт случайный вход непосредственно на GPU;
4. прогревает модель;
5. измеряет latency;
6. измеряет peak memory;
7. измеряет energy;
8. записывает строку CSV сразу после каждой конфигурации;
9. перехватывает OOM;
10. может продолжить прерванный запуск.

При seed 7 получаются дополнительные значения:

```text
S_random = 144, 272, 304, 448
B_random = 18, 24, 219
```

Разделение:

```text
63 base×base точки       → calibration
69 точек с random S/B    → validation
```

Latency измеряется CUDA events после прогрева. Число повторов адаптируется к
длительности конфигурации, а итогом становится медиана.

Energy измеряется примерно за одну секунду повторов:

- накопительным счётчиком NVML, если он доступен;
- иначе усреднённой NVML-мощностью, умноженной на время.

### 3.5. `calibrate.py`: подбор параметров

Для latency подбираются три положительных параметра:

```text
t_launch, P_eff, BW_eff.
```

Минимизируется разница логарифмов измеренного и предсказанного времени. Это
позволяет учитывать и короткие, и длинные конфигурации.

Для energy подбираются:

```text
e_launch, e_flop, e_byte.
```

Используется non-negative least squares — коэффициенты не могут стать
отрицательными.

Отдельно рассчитываются метрики для calibration и validation:

- MAE;
- RMSE;
- MAPE;
- median absolute percentage error;
- `R²`.

### 3.6. `plots.py`: визуальная проверка

Код должен создать пять файлов:

```text
latency_surface.png
memory_surface.png
energy_surface.png
predicted_vs_measured.png
latency_regimes.png
```

Поверхности содержат предсказание и настоящие точки. На memory-графике OOM
показывается красными крестами. Scatter сравнивает measured и predicted, а
regime-график показывает launch-, memory- и compute-bound области.

## 5. Что именно нужно написать от руки

Подробный буквальный сценарий находится в
`HANDWRITTEN_DERIVATION_GUIDE.md`. Там указано, что писать на каждой странице,
какие числа брать из архитектуры и как получать коэффициенты.

Рекомендуемая структура рукописного PDF:

### Страница 1. Обозначения и формы

Нужно написать:

- вход `B×3×S×S`;
- `S` кратно 16;
- формулу выходного размера слоя;
- форму и количество элементов после каждого слоя;
- предположения FP32, inference, TF32 off, `1 MAC = 2 FLOP`.

### Страница 2. Параметры

Нужно отдельно посчитать параметры всех шести свёрток и двух Linear, затем
сложить их:

```text
1 040 324 параметра.
```

### Страница 3. FLOPs

Нужно:

1. написать общую формулу свёртки;
2. подставить размеры для каждой из шести свёрток;
3. отдельно посчитать ReLU, MaxPool, GAP и Linear;
4. показать сложение всех коэффициентов.

Важно: `S` и `B` остаются переменными. Подставляются только каналы, размеры
ядер, stride и число классов.

### Страница 4. Memory

Нужно показать, какие тензоры одновременно живут во время каждого крупного
этапа. Максимум возникает на MaxPool:

```text
3BS² + 8BS² + 2BS² = 13BS².
```

После этого добавить параметры и умножить на 4 байта.

### Страница 5. BytesMoved

Для каждого из 17 операторов записать:

```text
вход + веса/bias + выход.
```

Затем отдельно сложить коэффициенты при `BS²`, при `B` и постоянную часть.

### Страница 6. Latency

Нужно вывести:

```text
t_compute = F_l/P_eff
t_memory = Q_l/BW_eff
t_l = t_launch + max(t_compute, t_memory)
```

После этого сложить времена 17 операторов и объяснить параметры `θ`.

Численные `θ` от руки придумывать не нужно — они появляются после
калибровки.

### Страница 7. Energy и эксперимент

Нужно объяснить три слагаемых energy, параметры `θ_E`, сетку 132 точек,
calibration/validation и обработку OOM.

После написания страницы нужно отсканировать или сфотографировать, проверить
читаемость и объединить в `hw1_handwritten.pdf`.
